Terminas un proyecto, escribes su README y después no sabes cómo presentarlo fuera de GitHub. Publicar “hice una app con React” dice qué herramienta utilizaste, pero no explica por qué alguien debería probarla. **Tu README puede ser la fuente de una explicación útil para redes**, sin convertirse en una copia de instrucciones de instalación.

En esta guía vamos a extraer una historia demostrable y preparar un carrusel, una portada y un texto breve. Utilizaremos las [herramientas gratuitas de Antrapost](https://www.antrapost.com/tools?utm_source=ulises_io&utm_medium=referral&utm_campaign=antrapost_guides&utm_content=es_convertir-readme-proyecto-contenido-redes), uno de mis proyectos, que no requieren registro para este trabajo.

## Extrae cuatro piezas del README

Antes de diseñar, identifica el problema, una acción visible, una decisión técnica y el enlace para probar. Si falta alguna, quizá el siguiente paso sea mejorar la documentación, no escribir un anuncio.

| Parte del README | Pregunta que responde | Pieza que puedes crear |
| --- | --- | --- |
| Objetivo | ¿Para quién existe este proyecto? | Primera línea del anuncio |
| Demo y capturas | ¿Qué puede hacer una persona? | Portada o imagen demostrativa |
| Decisiones | ¿Qué elegiste y por qué? | Una explicación en carrusel |
| Cómo probar | ¿Cuál es el siguiente paso? | Enlace y acción final |

No necesitas contar todas las dependencias. El lector que quiere probar una aplicación tiene otras preguntas que la persona que quiere clonar su repositorio.

## Paso 1: elige una acción que puedas demostrar

Para una aplicación de gastos, “administrar información” es demasiado amplio. “Registrar un gasto y ver el total del mes” ofrece algo observable.

Abre la demo y realiza esa acción. Usa datos de ejemplo y evita mostrar credenciales, información personal o paneles privados. Si el proyecto no está desplegado, puedes enseñar una captura local, pero no presentarla como una demo pública disponible.

La [guía de proyectos para el CV](/blog/proyectos-valiosos-para-tu-cv-programador) ayuda a preparar una demo y un README que puedas defender durante una entrevista.

## Paso 2: prepara una captura legible

Una captura de todo el escritorio suele incluir más ruido que información. Conserva la zona que explica la acción y revisa que los textos importantes se lean en un teléfono.

El [redimensionador de Antrapost](https://www.antrapost.com/tools/image-resizer?utm_source=ulises_io&utm_medium=referral&utm_campaign=antrapost_guides&utm_content=es_convertir-readme-proyecto-contenido-redes) permite recortar o mantener la imagen completa con un fondo. Si el archivo pesa demasiado, utiliza el compresor después de decidir el encuadre.

No alteres la captura para mostrar una función que no existe. Una composición puede presentar mejor el material; no debería inventar el resultado.

## Paso 3: explica una decisión en pocas láminas

Una secuencia posible es: problema, enfoque elegido, dificultad, comprobación y siguiente paso. No es obligatorio llenar todas las láminas; cada una debería aportar una idea.

Con el [creador de carruseles](https://www.antrapost.com/tools/carousel-maker?utm_source=ulises_io&utm_medium=referral&utm_campaign=antrapost_guides&utm_content=es_convertir-readme-proyecto-contenido-redes), escribe un bloque por lámina y sepáralos con `---`. El editor permite hasta diez y descarga PNG individuales o un ZIP.

Por ejemplo, puedes explicar por qué validas datos también en el servidor. Muestra qué error querías evitar y cómo comprobaste el comportamiento. “Usé buenas prácticas” no dice cuál fue tu decisión; un caso concreto sí permite evaluarla.

## Paso 4: escribe un anuncio que no duplique todo

El caption no necesita transcribir el carrusel. Presenta el problema, adelanta el valor de la explicación y ofrece una acción concreta: probar la demo, leer el README o comentar una decisión.

El [contador de caracteres](https://www.antrapost.com/tools/caption-character-counter?utm_source=ulises_io&utm_medium=referral&utm_campaign=antrapost_guides&utm_content=es_convertir-readme-proyecto-contenido-redes) ayuda a comparar borradores. Su objetivo de longitud es personal, no un límite oficial de cada red ni una evaluación de calidad.

Elige una sola acción principal. Tres enlaces y cinco invitaciones pueden hacer menos claro qué debería hacer la persona después de leer.

## Paso 5: conserva la evidencia y revisa el destino

Guarda el texto original, las imágenes exportadas y el enlace de la versión que mostraste. Las herramientas gratuitas procesan en el navegador y no conservan tus borradores después de salir.

Abre el enlace en una ventana privada y revisa el contenido que verá alguien sin tu sesión. Después usa la [checklist de publicación](https://www.antrapost.com/tools/post-checklist?utm_source=ulises_io&utm_medium=referral&utm_campaign=antrapost_guides&utm_content=es_convertir-readme-proyecto-contenido-redes) para comprobar archivos, cuentas y horarios.

## Qué no convertir en una promesa

No presentes un tutorial copiado como una arquitectura original ni una demo pequeña como un sistema probado a gran escala. Puedes explicar lo que aprendiste, reconocer la fuente y describir el trabajo que sí hiciste.

Si utilizaste IA, cuenta qué verificaste y qué decisiones puedes explicar. Compartir un proyecto debería ayudarte a conversar sobre él, no crear un relato que luego no puedas sostener.

## Un ejemplo de transformación, sin inventar una historia

Un README y una publicación responden preguntas distintas. El primero puede explicar cómo ejecutar el proyecto; la segunda necesita mostrar por qué la tarea importa y qué puede probar el lector. Reutilizar no significa pegar el mismo texto en otro formato.

Supón que tu README dice «importación CSV con validación por fila». Puedes convertirlo en una explicación: «un archivo con una fecha inválida no debería bloquear todos los registros. Esta demo muestra cuáles acepta y cuáles debes corregir». Ese texto solo corresponde si el proyecto realmente se comporta así.

La captura puede mostrar una fila aceptada y una rechazada con datos ficticios. El caption aclara el alcance y enlaza la demo o el repositorio. No hace falta afirmar que ahorraste horas o conseguiste usuarios para enseñar una decisión útil.

Si buscas un plan de presentación y seguimiento, utiliza la [guía de lanzamiento del side project](/blog/lanzar-side-project-redes-plan-publicaciones); aquí el trabajo consiste en extraer y adaptar una pieza de documentación.

## Preguntas frecuentes

### ¿Necesito escribir un README enorme?

No. Necesitas información suficiente para entender, ejecutar y evaluar el proyecto. La extensión depende de lo que deba explicar, no de una cantidad fija de palabras.

### ¿Puedo preparar todo sin una cuenta de Antrapost?

Puedes usar las herramientas gratuitas para crear y descargar el material sin registro. Publicar o programar dentro del producto es un flujo separado con sus propias condiciones.

### ¿Qué hago si mi proyecto todavía está incompleto?

Comparte un avance concreto y sus límites. Indica qué funciona y qué falta; no lo anuncies como una solución terminada.

### ¿Puedo publicar instrucciones de instalación tal como están?

Puedes, pero revisa si responden a la necesidad de tu audiencia. Para presentar el proyecto suele ayudar primero una tarea demostrable; deja las instrucciones completas en el repositorio.

### ¿Cómo reconozco trabajo basado en un tutorial?

Nombra la fuente y separa el punto de partida de tus cambios. Explica una decisión o función propia que puedas demostrar sin presentar todo el proyecto como creación original.
